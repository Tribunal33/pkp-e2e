# A comment report the server refuses closes like a sent one: no message, the reason lost

Defect. OJS at the PR heads of dev-team#316 before their merge, second
round: ojs `95ffb63be4` (ojs#5810), lib/ui-library `f4f61bfd`
(ui-library#992), lib/pkp `fa516111fa` (pkp-lib#13292),
plugins/generic/crossref `9b10eb6` (crossref-ojs#108). Introduced by
ui-library#992's `usePkpFetch` fix meeting the comments store's existing
`closeTopDialog()`; on `main` the same refusal also shows nothing (the
fetch throws and the window stays open). OMP and OPS: their frontend
bundles carry no `usePkpFetch`, not affected. Merged unchanged
2026-09-29 (ui-library merge `280f98c5`, ojs `efd71c9e0e`); register
entry U14 A14. The behaviour predates the change, so the team files it
as its own issue (thread, 2026-09-29). Temporary: delete once acted on.

## Summary

A signed-in reader reports a comment and the server refuses the report
(any error answer). The "Report Comment" window closes exactly as after a
successful report: no error message, the typed reason gone, the comment
not marked as reported.

## Impact

Rare (the report must fail on the server), but the reader believes the
report was sent and the moderators never get it. Minor.

## Steps to reproduce

Preconditions: OJS at the PR heads above, a journal with public comments
on, a published article with an approved comment by another reader.

1. Signed in as a reader, open the article page.
2. On the other reader's comment press "…" › "Report", type a reason.
3. Make the report request fail (the probe answers
   `POST …/api/v1/comments/<id>/reports` with a 500 in the browser).
4. Press "Submit".

**Expected**: an "Error" window with the server's message; the report
window kept (or reopenable) with the reason.

**Observed**: both windows are gone within a second; nothing tells the
reader the report failed.

Controls in the same run: a refused new comment shows "Error" with the
server's message, the text stays in the box, "Submit" re-enabled; a
refused "Delete Comment" shows one "Error" window (after `f4f61bfd`;
`d458b2e1` showed two).

## Cause

`usePkpFetch` (frontend) now opens `openDialogNetworkError` for a failed
POST, on top of the report window. `performCommentReport()` in
`src/frontend/components/PkpComments/usePkpCommentsStore.js` then calls
`closeTopDialog()` unconditionally, which closes that error window (the
top one), and the Submit callback's `close()` closes the report window.

## Proposed fix

Drop the `closeTopDialog()` from `performCommentReport()` (the Submit
callback's `close()` already closes the report window), or pass
`onError: () => true` there and open the error window after `close()`,
as the delete path now does. Side note on that delete path: it calls
`openDialogNetworkError()` without the error, so the reader gets "An
unexpected error has occurred…" instead of the server's message.
