## Summary

On 3.5, an editor who opens "More Information" on a file that was
copied from an earlier stage (a file in "Files for Review" chosen from
the submission's files, a file promoted to Copyediting or Production)
and clicks the "Notes" tab gets an empty tab. The server fails behind
it. No note form, no notes, and no "Earlier Revision Notes" show, and
no message says why.

Notes cannot be added to such a file, and the notes left on the file
it was copied from cannot be read from it. The "History" tab and the
notes of files that were uploaded directly (not copied) still work.

## Impact

- **Lost**: the file's notes, both reading and adding them, on every
  copied file. Nothing stored is lost; the notes are only out of reach.
- **Who**: editors and section editors (press editors in OMP) using a
  file's "More Information" in Review, Copyediting or Production, where
  most files are copies. Every 3.5 release has it.
- **Way round**: notes left on the original file can still be read from
  that file in its own stage, and a note can be left there instead.
  Nothing works from the copy itself.

Medium: a secondary task fails for every copied file on every 3.5
install, with a partial way round through the original file; it would
be high if file notes were the team's only channel for that file.

## Steps to reproduce

Preconditions: the default dataset, OJS `stable-3_5_0`.

1. Sign in as `dbarnes`.
2. Open "Finocchiaro: Arguments About Arguments" (submission 19) from
   the Dashboard.
3. In the side menu, under "Workflow", open "Review" › "Review Round 1".
4. Under "Files for Review", open the "⋯" menu of
   "Finocchiaro: Arguments About Arguments.pdf" (file 43) and choose
   "More Information".
5. Click the "Notes" tab.

The same on OMP: "The West and Beyond: New Perspectives on an Imagined
Region" (submission 2), "Review Round 1", "chapter4.pdf" (file 12).

**Expected**: the tab shows "There are no notes to display.", an "Add
Note" form, and a collapsed "Earlier Revision Notes" section, as it
does on `main`.

**Observed**: the tab stays empty. The request behind it answers 500:

```
GET /index.php/publicknowledge/$$$call$$$/information-center/file-information-center/view-notes?submissionId=19&submissionFileId=43&stageId=3 → 500
PHP Fatal error:  Uncaught Error: Class "PKP\controllers\informationCenter\Note" not found in lib/pkp/controllers/informationCenter/FileInformationCenterHandler.php:141
```

The same file's "History" tab answers 200, and on "Submission Files"
the original (file 42) opens its "Notes" tab normally.

## Cause

`FileInformationCenterHandler::viewNotes()` reads the notes of the file
a copy came from when `sourceSubmissionFileId` is set:

```php
$notes = Note::withAssoc($this->_getAssocType(), $sourceSubmissionFileId)->get();
```

The file has no `use PKP\note\Note;`, so PHP resolves `Note` in the
handler's own namespace, `PKP\controllers\informationCenter`, where no
such class exists. `pkp/pkp-lib#10268` converted notes to an Eloquent
model and replaced the `NoteDAO::getByAssoc()` call here with
`Note::withAssoc()`, without the import. A file that is not a copy
skips that branch, which is why only copies fail.

`main` gained the missing import in `pkp/pkp-lib#12286` (a JATS file
revision change that touched the handler's imports); 3.5 was branched
before it and never received that change.

Reach:

- OJS and OMP 3.5: every copied file in Review, Copyediting and
  Production (walked on both).
- OPS 3.5: no screen reaches it; galleys have no "More Information"
  (walked).
- Nowhere else: the parent `InformationCenterHandler`, which lists,
  saves and deletes notes, imports `Note`, and a search of 3.5's
  `controllers`, `pages`, `classes` and `api` for `Note::` in a file
  without the import finds only this handler (code).

## Proposed fix

Add the missing import to the 3.5 handler
([fix-stable-3_5_0.diff](https://github.com/jardakotesovec/pkp-e2e/blob/main/shared/playwright/checks/sync/pkp-lib-10268/fix-stable-3_5_0.diff)):

```diff
 use PKP\log\event\EventLogEntry;
+use PKP\note\Note;
 use PKP\notification\Notification;
```

It is the same line `main` already carries. Tried on 3.5 OJS and OMP:
the "Notes" tab of the copied file shows "There are no notes to
display.", the "Add Note" form and "Earlier Revision Notes", as on
`main`.

- **Alternatives**: backporting all of `pkp/pkp-lib#12286` would bring
  the line in too, along with an unrelated JATS feature.
- **What goes with it**: nothing stored needs repair. A handler test
  that opens "Notes" on a copied file would have caught it.

Small: one line in one file on `stable-3_5_0`.
