## Summary

With metadata lookup on, an editor creates a new version while the
current version's references are still being looked up. The new version
gets copies of those references, still marked as being looked up, but
the lookups under way work on the originals only. The copies are never
looked up, and with this PR the new version's box reads "Processing
references - 0/n" for good, with the page re-fetching the submission and
the publication every 7 seconds while it is open. On `main` today the
box does not show, and the copies are just as silently never looked up.

## Impact

- **Lost** Nothing stored. The copies never get the details or the "No
  structured information found" badge the lookup would give, and the
  editor is told a lookup is running that never will.
- **Who** Editors on journals, presses and servers with "Enable
  references structuring and metadata lookup" on, who create a new
  version within the minute or two a lookup takes, or within the hours
  it takes while a service is unreachable or rate-limited (a failing
  lookup is retried for about a day).
- **Way round** "Reprocess" on each copy, or "Reprocess all references"
  in the new version, asks a lookup of its own.

Low: a narrow window, nothing lost, and a way round on screen.

## Steps to reproduce

Preconditions: PKP's default test dataset for `main` (OJS), the PRs
checked out (ojs `dd6adba109`, lib/pkp `0dc8d84fc7`, lib/ui-library
`0185ab12`, frontend rebuilt). The install cannot reach the lookup
services, so the lookups stay under way; step 7's SQL stands in for the
originals' lookups finishing (`IsProcessedJob::handle()` stores 5).

1. Sign in as `dbarnes` (password `dbarnesdbarnes`).
2. Open "Settings" › "Workflow" › "Metadata", tick "Enable references
   structuring and metadata lookup" and press "Save".
3. Open submission 17 (published, one version), "Publication" and
   "Unpublish" it.
4. Open "References", type these three lines and press "Add":

   ```
   u42r9 Reference one. Test Press; 2020.
   u42r9 Reference two. Test Press; 2020.
   u42r9 Reference three. Test Press; 2020.
   ```

   The box reads "Processing references - 0/3".
5. "Publish" the version again.
6. "Create New Version".
7. Let the originals' lookups finish:

   ```sql
   UPDATE citation_settings SET setting_value = '5'
    WHERE setting_name = 'processingStatus'
      AND citation_id IN (SELECT citation_id FROM citations
                           WHERE publication_id = 18 AND raw_citation LIKE 'u42r9%');
   ```

8. Open the new version's "References", look under the "Add" box and
   watch the browser's network panel for 30 seconds.

**Expected.** The copies are looked up like any reference added with
lookup on, and the box counts down to "All 3 references successfully
processed".

**Observed.** "Processing references - 0/3", and `GET submissions/17`
with `GET submissions/17/publications/22` every 7 seconds. The copies
stay at stored status 1 (`PID_EXTRACTED`); the queued jobs carry the
originals' citation ids (1, 2, 3), not the copies' (4, 5, 6).

## Cause

`PKP\citation\Repository::copyCitations()`, which
`publication\Repository::version()` calls, inserts each citation with
its data, the stored `processingStatus` included. A citation copied at
`QUEUED` or a lookup stage (1 to 4) keeps it, but the chain that would
move it on was queued with the original's id. The PR's store counts
every citation with a status other than `NOT_PROCESSED` or none, and
waits for it to reach `PROCESSED` or `FAILED`, so the copies hold the box
and its refresh for good. Before the PR the box counted structured
references only, so the unstructured copies were left out and nothing
showed.

## Proposed fix

In `copyCitations()`, a copy whose status is `QUEUED` or a stage before
`PROCESSED` gets a lookup of its own after its insert
(`reprocessCitation()`, which stores `QUEUED`) when lookup is on in its
context, and `NOT_PROCESSED` when it is off. The team's earlier fix for
pkp-e2e#883 had this part
([fix.diff](https://github.com/jardakotesovec/pkp-e2e/blob/main/shared/playwright/checks/issues/reference-lookup-progress-counts-structured-only/fix.diff),
`copyCitations`), with the context read from the publication when the
request has none (CLI). Small: one method in pkp-lib, with a unit test
that a copied `QUEUED` citation is queued again.
